# OCR 封口贴检测系统 V3

## 概述

`ocr_batch_process_v3.py` 是封口贴合规检测系统的第三版，相对 V2 在**检出率**和**处理速度**上有显著提升。

核心设计理念：**宽松识别、精准拦截**。
- 宽松：放宽背面识别条件和位置容差，减少误判漏识别
- 精准：非官方贴纸颜色检测保持严格，专注检出真正违规行为

---

## V3 相对 V2 的核心改动

| 改动点 | V2 | V3 |
|---|---|---|
| **背面识别条件** | OCR 到"扫码即领" + 包装盒检测通过（fallback 跳过） | 只要 OCR 到"扫码即领"即为背面，fallback 不跳过 |
| **图片扫描策略** | 遍历所有图片取最优候选 | 找到第一张背面即停止，节省约 50% OCR 时间 |
| **角度验证** | 有（偏角 >30° → 不合规） | **已移除**，不再影响合规判定 |
| **位置容差** | ±0.15 | **±0.25**（贴纸超出包装盒边界仍合规） |
| **非官方贴纸输出** | 混在 position_valid=4 中 | 新增独立列"是否存在非官方贴纸" |
| **无背面时结果** | position_valid=-1 | 是否规范粘贴=0（更直观） |
| **非官方贴纸颜色检测（V3.1）** | 全图颜色检测 | **仅在"扫码即领"贴纸附近 ROI 内检测 + 面积比例相对全盒计算** |

## 检测流程

```
┌─ Step 1: 背面识别 ─────────────────────────────────────────────────────┐
│  遍历订单的 1~4 张图片（并行预下载）                                    │
│  找到第一张 OCR 检测到"扫码即领"的图片 → 确认为背面，停止扫描          │
│                                                                          │
│  无背面图 → 是否规范粘贴 = 0                                            │
└──────────────────────────────────────────────────────────────────────────┘
         ↓ 有背面图
┌─ Step 2: 非官方贴纸检测（仅对背面图）─────────────────────────────────┐
│  对背面图做包装盒透视矫正（perspective → rotation → axis_aligned 三级） │
│  在矫正后的包装盒区域做颜色检测（V3.1 改进策略）：                      │
│    1. 先用 OCR 定位"扫码即领"贴纸中心                                   │
│    2. 仅在贴纸中心 ±30% zone 尺寸的 ROI 内做颜色分析                   │
│       （ROI 以外的官方印刷元素如 AirPods 紫色授权条带完全被排除）        │
│    3. 面积占比相对整个 zone 计算，避免 ROI 较小导致阈值虚高             │
│    4. 白色背景像素不足时跳过检测（拍摄角度/光线不佳场景的保护）         │
│    • 白盒（iPhone/Watch/AirPods/Accy./iPad）：白平衡归一化 + 相对饱和度│
│    • 棕盒（Mac）：排除棕色 + 排除白色 + 绝对饱和度                      │
│                                                                          │
│  检出非官方贴纸 → 是否存在非官方贴纸=1，是否规范粘贴=0                 │
└──────────────────────────────────────────────────────────────────────────┘
         ↓ 无非官方贴纸
┌─ Step 3: 贴纸位置验证（放宽容差，无角度约束）────────────────────────┐
│  ① 在矫正坐标系中定位"扫码即领"贴纸位置（相对坐标 rel_x / rel_y）     │
│  ② 验证位置是否在 LOB 规范区域内（容差 ±0.25，超出包装盒也算合规）     │
│  ③ 平铺检测：贴纸端片（Authorized Reseller）可见 → position_valid=2   │
│  ④ 双贴检测：                                                           │
│      • 单贴（AirPods/Accy.）：只验证扫码贴位置                         │
│      • 单/双贴（iPhone/Watch/iPad/Mac）：                               │
│          - 有 Apple授权专营店 → 验证双贴位置                           │
│          - 仅扫码贴 → 单贴合规                                          │
│                                                                          │
│  位置合规 → 是否规范粘贴 = 1                                            │
└──────────────────────────────────────────────────────────────────────────┘
```

## 非官方贴纸检测逻辑说明（V3.1）

### 为什么改为 ROI 局部检测？

AirPods 官方白色包装盒上有多处彩色印刷元素：
- 右侧紫色「Apple授权专营店 在你身边」竖向条带
- 盒面两个绿色回收箭头符号
- 「扫码即领」圆形贴纸本身的绿色边框设计

旧方法对整个矫正盒面做颜色分析，会把这些官方印刷元素误判为「非官方贴纸」。

新方法只检测贴纸中心附近的区域（±30% zone尺寸），并且面积阈值仍相对整个盒面，这样：
- 贴纸 ROI 以外的官方元素完全被忽略
- 真正的非官方贴纸（覆盖在官方贴纸上方）才会触发

### 何时会跳过颜色检测？
1. LOB 配置中 `enabled: false`（如 Mac 棕盒需用 brown_box 模式）
2. 在背面图中找不到「扫码即领」贴纸中心（仅回退全图检测）
3. ROI 内白色背景像素不足 800px（拍照角度差/强反光时的保护措施）

## 各 LOB 规范位置配置

> 坐标系：透视矫正后以包装盒左上角为原点，右下角为 (1.0, 1.0)。
> 实际判定时在配置区域基础上再 ±0.25 容差。

| LOB | 贴纸类型 | X 范围 | Y 范围 | 备注 |
|---|---|---|---|---|
| iPhone | 扫码即领（单贴或双贴） | 0.50 ~ 0.95 | 0.00 ~ 0.30 | 右侧上方 |
| iPhone | Apple授权专营店（双贴） | 0.50 ~ 0.95 | 0.70 ~ 1.00 | 右侧下方 |
| Watch | 封口贴（单贴或双贴） | 不约束 | 0.00~0.45 或 0.55~1.00 | 顶端或底端 |
| AirPods | 扫码即领（单贴） | 0.50 ~ 0.95 | 0.00 ~ 0.50 | 右侧 |
| Accy. | 扫码即领（单贴） | 0.50 ~ 0.95 | 0.00 ~ 0.50 | 右侧 |
| iPad | 扫码即领（单贴或双贴） | 0.50 ~ 0.95 | 0.00 ~ 0.30 | 右侧上方 |
| iPad | Apple授权专营店（双贴） | 0.50 ~ 0.95 | 0.70 ~ 1.00 | 右侧下方 |
| Mac | 扫码即领（单贴或双贴） | 0.25 ~ 0.75 | 0.70 ~ 1.00 **或** 0.00 ~ 0.30 | 下方居中 **或** 上方居中（镜像均合规） |
| Mac | Apple授权专营店（双贴） | 0.05 ~ 0.50 **或** 0.50 ~ 0.95 | 0.00 ~ 0.30 | 上方左侧 **或** 上方右侧（镜像均合规） |

## 输出列说明

| 列名 | 类型 | 说明 |
|---|---|---|
| `识别LOB` | str | iPhone / Watch / AirPods / Accy. / iPad / Mac / UNKNOWN LOB |
| `是否规范粘贴` | int | **0=不合规 \| 1=合规**（总判断） |
| `封口贴存在` | int | 0=未检测到 \| 1=检测到 |
| `是否存在非官方贴纸` | int | **0=无 \| 1=检出非官方贴纸**（新增列） |
| `贴纸位置规范` | int | -1=无贴纸 \| 0=位置异常 \| 1=位置规范 \| 2=平铺错误 \| 4=非官方贴纸 |
| `贴纸相对X` | float | 贴纸中心 X 坐标（相对包装盒宽度，0~1） |
| `贴纸相对Y` | float | 贴纸中心 Y 坐标（相对包装盒高度，0~1） |
| `包装盒检测方式` | str | perspective / rotation / axis_aligned |
| `矫正方式` | str | perspective / rotation / axis_aligned |
| `包装盒四点坐标` | str | 原图 4 角点 JSON（axis_aligned 时为空） |
| `颜色检测已执行` | int | 0=未执行 \| 1=已执行 |
| `颜色检测模式` | str | white_box / brown_box / 空 |
| `位置说明` | str | 详细说明（含坐标、异常原因） |
| `双贴纸状态` | int | -1=无贴 \| 0=单贴 \| 1=双贴合规 \| 2=两扫码贴 \| 3=缺二贴 |
| `双贴纸说明` | str | 双贴检测详细说明 |
| `时间` | str | 水印时间（从图片底部区域提取） |
| `地点` | str | 水印地点（从图片底部区域提取） |

## 合规判定逻辑树

```
LOB 识别失败
  └─→ 是否规范粘贴=0

无背面图（无"扫码即领"）
  └─→ 是否规范粘贴=0

有背面图
  ├─ 颜色检测命中非官方贴纸
  │    └─→ 是否存在非官方贴纸=1，是否规范粘贴=0
  │
  ├─ 贴纸平铺（Authorized Reseller 端片可见）
  │    └─→ 贴纸位置规范=2，是否规范粘贴=0
  │
  ├─ 贴纸位置超出规范区域（含容差）
  │    └─→ 贴纸位置规范=0，是否规范粘贴=0
  │
  ├─ 单贴位置合规
  │    ├─ single_only LOB（AirPods/Accy.）
  │    │    └─→ 是否规范粘贴=1 ✓
  │    │
  │    └─ single_or_dual LOB（iPhone/Watch/iPad/Mac）
  │         ├─ 无 Auth 贴纸 → 是否规范粘贴=1 ✓
  │         ├─ Auth 贴纸位置合规 → 是否规范粘贴=1 ✓
  │         └─ Auth 贴纸位置异常 → 是否规范粘贴=0
  │
  └─ 两张扫码贴（位置均合规）
       └─→ 是否规范粘贴=1 ✓（贴纸类型记录为 dual_code=2 供人工复查）
```

## 快速开始

### 环境要求

```bash
pip install paddleocr paddlepaddle-gpu opencv-python pillow pandas openpyxl requests
```

> GPU 版 PaddlePaddle 安装参考：[PaddlePaddle 官方安装指南](https://www.paddlepaddle.org.cn/install/quick)

### 修改输入输出路径

打开 `ocr_batch_process_v3.py`，修改 `main()` 函数中的路径：

```python
input_file   = '/home/ubuntu/OCR/W5.xlsx'       # 输入 Excel
output_csv   = '/home/ubuntu/OCR/W5_v3_results.csv'
output_json  = '/home/ubuntu/OCR/W5_v3_results.jsonl'
output_excel = '/home/ubuntu/OCR/W5_v3_processed.xlsx'
```

### 运行

```bash
cd /home/ubuntu/OCR
python ocr_batch_process_v3.py
```

### 断点续传

程序会自动检测已有 CSV 输出，跳过已处理的订单号，直接从断点继续。

## 性能说明

- **OCR 加速**：找到背面图即停止扫描，平均减少约 50% OCR 调用
- **并行下载**：8 线程并行预下载（DOWNLOAD_WORKERS=8），配合 3 行预取队列
- **GPU 推理**：PaddleOCR 使用 GPU 加速，建议在有 GPU 的机器上运行

---

## 可调参数

```python
IMAGE_COLUMNS           = ['图片地址', 'Unnamed: 17', 'Unnamed: 18', 'Unnamed: 19']
DOWNLOAD_WORKERS        = 8      # 并行下载线程数
STICKER_POSITION_TOLERANCE = 0.25  # 位置容差（相对坐标系，贴纸超出包装盒此比例内仍合规）
BOX_DETECT_MAX_SIDE     = 1200   # 包装盒检测最大分辨率
```
